5. 後續規劃 規劃中

依上週四會議討論,HP 後續有計劃開發自己的 APP;
由 Demo 影片來看,內容包含 Note、Calendar 等相關應用。

HP 亦提出需求 - 希望我方提供相關 SDK 協助開發。
SDK 聚焦於以下三項:

  • E-ink 手寫加速。
  • Refresh API。
  • ENT 格式輸出結構客製化:我方協助客製 ENT 輸出結構,讓 HP 介接時能接上手寫功能,並可與 Windows 端雙向溝通。

此外,我方會提供一份 Demo App 原始碼,可展示 SDK 的大致使用方式,以及如何實做相關應用(例:Multi-Layer)。

SDK 範疇(如上次會議所提):SDK 本意是針對 E-ink 裝置的手寫速度 / 開關水 / 筆觸 / 刷新等;
整體筆記的結構與架構屬開發端可彈性開發的部份,SDK 並不提供這些內容。

因此其他工具的功能展示皆需額外開發時間(例:套索、圖形、Multi-Layer、插入圖片、背景等);
目前時程仍在評估,待後續更新。

5. Next Steps / Planning planning

Per last Thursday's meeting, HP plans to build their own app; from the demo video, it covers Note, Calendar and related applications.

HP also requested that we provide an SDK to assist development. The SDK focuses on three areas:

  • E-ink handwriting acceleration.
  • Refresh API.
  • Customized ENT output structure: we help customize the ENT output structure so HP can hook into the handwriting features when integrating, and enable bidirectional communication with the Windows side.

In addition, we will provide a Demo App source code to show roughly how the SDK is used and how to implement related features (e.g., Multi-Layer).

SDK scope (as noted last meeting): the SDK is meant for e-ink handwriting speed / ink on-off / stroke / refresh on the device; the overall note structure and architecture is the developer's flexible part - the SDK does not provide these.

So demonstrating other tools requires extra development time (e.g., lasso, shapes, Multi-Layer, image insertion, background); the timeline is still being evaluated and will be updated later.
